Our Hierarchical RAG (HiRAG) framework must be built in storage/vector_store.py. Stop treating this like a flat, standard vector search. It must look up information using three distinct architectural layers:

1. The Local Layer (The Details): > * This stores raw, fine-grained text chunks and their individual vector embeddings (e.g., specific dialogue lines, single item descriptions, or specific code snippets).

2. The Global Layer (The Big Picture / Themes): > * The system must recursively cluster those local nodes together to find their 'thematic centers' (centroids). Each cluster represents a broader global concept or overarching story theme (e.g., 'The History of the Ruins' or 'Character Magic Rules').

3. The Bridge Map (The Connection): > * This is a hard relational lookup index that directly binds every granular Local Node to its parent Global Cluster.

How Retrieval Works (Multi-Hop Search):

When a query comes in, you do not just scan the local chunks. You scan the Global Layer first to find the broad thematic cluster that matches the user's intent.

Once you find the correct global theme, you use the Bridge Map to instantly hop down and extract the highest-scoring, fine-grained Local Nodes inside that specific cluster.

Build the complete data structures and search functions using this exact three-layer logic inside our flat-file JSON format. Do not use placeholders or external database wrappers.
